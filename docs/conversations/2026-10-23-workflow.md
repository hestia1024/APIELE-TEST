# 2026-10-23：协作发布流程建立

## 用户原始需求

> 我现在需要一个用于规范化发布的流程规则：该对话需要动项目代码-自动检测git仓库版本-有更新则拉取-正常写代码-收到明确需要发布的指令-提交代码-上传服务器，每一步完成后都会有提示，不仅我要用，协作者也需要用，所以上传仓库的不仅是项目，还包括该对话的一切内容和记录

## 已落实的决定

根目录 `AGENTS.md` 作为共享 Codex 规则；`workflow.py prepare` 是开发前入口，`workflow.py release` 是明确发布后入口。提交和部署之间要求先成功推送 GitHub，保证同事能够拉到已上线代码。只允许快进同步，遇到未提交修改与远端更新并存或历史分叉就停下，保留现场。

发布包从指定 Git 提交读取项目文件，不混入本地未提交代码；服务器记录提交号并检查网站和数据库。每个关键阶段输出完成/等待/失败提示。所有人的 SSH/数据库密码只在本机 `.env`，协作者各自配置 GitHub 凭据。

共享历史以脱敏文本、项目接手文档和操作记录保存在仓库。可读原始会话见同目录 `*-transcript.md`；不可得的历史、缺失附件和压缩上下文明确标记，不编造完整逐字档案，不上传可能含密码的截图原图或内部推理。
